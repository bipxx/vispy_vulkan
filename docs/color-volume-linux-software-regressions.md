Use the same24 predeclared public VolumeVisual inputs, methods, parameters,
whole-frame exact comparisons, before-frames, opacity controls and independent
plane landmarks as the qualified Windows packet. The fixture is unchanged.
A separate Linux adapter preserves the frozen Windows source/reference bytes;
its four quality/payload gate bodies are AST-held against that protocol.

This is one WSL Ubuntu/glibc2.39 CPython3.12.8 Mesa25.2.8 llvmpipe software cell.
The nine runtime package versions are the same as the Windows NumPy2.4.6 pair,
with newly compiled Linux wheel hashes. Pin six actual driver/LLVM inputs before
graphics. Force the original OpenGL llvmpipe renderer and the candidate Vulkan
CPU llvmpipe adapter; verify their real identities and pinned driver bytes.

9e8d65572d164a8ab690815feee9f7b6848fe5a3ce761a9082ad0580c398ff3f;
the archived audited Native58 Linux CP312 candidate wheel has SHA256
4c98f9c1456fdd4d43815aea624734b9b4c734083d381455bed7ee0140214070.

Create a fresh owned Xvfb with displayfd allocation and a new external runtime,
shader/cache directory. Finish all24 fresh original cases before any candidate.
Retain every raw array, before-frame, GLIR/shader/parameter artifact and failure.
If the original fails, no candidate runs. Every candidate case remains required.
Verify all archive payloads except installer-rewritten RECORD, native origins,
positive native work, actual terminal workers/parents and eight shutdown zeros.
Stop and wait the owned Xvfb before removing owned scratch. If actual worker
termination is unverified, preserve its environment, Xvfb and scratch with the
failure record for resolution. Never reuse or delete earlier evidence roots.

CPU controls, source/stack freeze and read-only review precede graphics. A
failed exact comparison is retained and does not authorize tolerance, pixel,
alignment, input or model changes. Fresh Linux OpenGL images are the reference;
the NVIDIA Windows packet is explicitly refused by the Linux adapter.

This does not qualify native Linux hardware, Metal, other ABIs/bindings, full
volume behavior or performance. No native rebuild, source/binary activation,
protected/heldout access or cleanup-rejection retry is part of this packet.
AGPL and the original BSD notices remain attached unchanged.


Source1 review refuses driver presence and inherited steering gaps before any
GPU. Source2 requires mapped GL Gallium/GLX/LLVM images for the original and
mapped Vulkan LVP/LLVM images for the candidate, checks their pinned bytes and
refuses unpinned driver-class substitutions. Upstream GL_RENDERER also requires
LLVM20. Selected driver environment is cleared in the outer launcher before
Xvfb or any child starts and again in each suite/worker, then the explicit
software profile is applied. Only the owned Mesa cache survives the worker
filter. Full relevant environment is recorded before and after capture.

Force QT_XCB_GL_INTEGRATION=xcb_glx and disable implicit Vulkan layers with
VK_LOADER_LAYERS_DISABLE=~implicit~, as documented by the primary
[Khronos loader interface](https://github.com/KhronosGroup/Vulkan-Loader/blob/main/docs/LoaderLayerInterface.md).
The explicit VisPy submit layer remains required and archive-verified. Xvfb must
still be alive before controlled shutdown, and forced kill is a failure. The
original-wheel pin is sealed, candidate wheel hash is asserted literally, and
owner-allocation failures after the fresh output directory exists are recorded.
No input, threshold, landmark, reference or exact comparison criterion changes.

renderer fixture, source adapter, 24 cases and all image criteria remain unchanged.
