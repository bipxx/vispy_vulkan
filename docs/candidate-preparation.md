## Executable workflows

| Workflow | Concrete behavior |
| --- | --- |
| `tools/tkinter_state_scenario.py` | Embedded red and standalone blue targets, real input/host binding, both flush routes, independent submission/completion/presentation counters, ordered green/blue readback, survivor redraw and host ownership. |
| `tools/tkinter_resource_scenario.py` | Shared Program, VertexBuffer and RGBA8 Texture2D; exact red targets; one public Timer callback uploads green and stops itself; blue survivor after first-consumer close; same widget/resources recover after native device recreation; explicit resource retirement and preserved host jobs/binding. |
| `tools/tkinter_failure_scenario.py` | Composite state/resource flow; a green-upload fault with original traceback and stopped public Timer, exact baseline cleanup, fresh resource/device recovery, and native-progress faults in both callback orders delivered once through a real external Tk loop, followed by explicit redraw recovery and preserved host work. |

The resource flow waits for a displayed image matching the *current* physical
extent and expected color. A PhotoImage from an earlier requested extent is not
readiness: Windows can acknowledge a wider minimum size. Full-frame GPU RGBA
and independent Tk corner values remain exact categorical assertions.

The injected timer-upload failure must reach the caller with its original
traceback while independent cleanup steps still run. Its scoped counters return
exactly to their starting values, preserving unrelated preexisting buffers.
The outer worker separately requires all nine gauges to be zero at process-wide
shutdown. Broad runs retained 1,160 bytes of unrelated CPU buffer state before
and after this workflow; resetting the runtime inside the test would hide that
ownership distinction and is not used.

Run these scripts with the selected environment only for functional inspection.
Their standalone execution does not prove installed-member identity or absence
of an OpenGL dependency/load/execution path. Manifest launch/install/auditor
commands are templates for an eventual isolated consumer and exact wheel;
dependencies and Tcl/Tk must already be separately pinned. No install/build or
observer job runs as a side effect of validating the declaration.

## Integrity and review boundary

```text
python -B tools/compatibility_candidate.py
python -B tools/compatibility_candidate.py --require-reviewed
```

The first checks the preparation schema, self identity, complete runtime source,
native source/header, build recipe/native extension source, lock and original
license inputs. Workflow scripts and acceptance fixture bytes are pinned. Every
proposal/profile has explicit local dependencies and actual workflow coverage;
missing acceptance modes, dependencies or mandatory host rows fail. Windows GPU
and WSL software identities cannot be exchanged. Previous qualified wheels keep
their historical scope; candidate wheels are deliberately null.

The second command currently fails because independent implementation/fixture
and proposal-scope reviews are pending. A review declaration must identify its
kind, independent reviewer and exact scope digest. Script, fixture, input or
verifier changes invalidate it. This checks content binding, not the truth of a
reviewer's independence; the independent review process remains mandatory.
Earlier Astra **plan** reviews do not approve implementation or this scope.

The v1 declaration is preparation only: even a correctly bound review cannot
make its output `installable` or `qualified`. It cannot hold a candidate wheel
or replace the canonical ledger, full installed-distribution/member auditor,
three original absence gates, native controls, CI or final promotion review.
Approved concrete scope still needs the conservation mechanism and residual
required obligations described in the compatibility specification. Ordinary
observer scripts alone do not prove all failure/recovery branches.
