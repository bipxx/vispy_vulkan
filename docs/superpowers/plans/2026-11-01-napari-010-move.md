# Move every napari row to napari 0.10.0 (D31) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every qualified napari row runs on napari 0.10.0. napari 0.9.2 rows are retired.

**Architecture:** Each phase moves one group of rows the way W16 and D30 moved the Windows PyQt6 rows:
- a host lock in `compat/host-environments/` with napari 0.10.0;
- where a suite pins napari 0.9.2, a version-agnostic successor beside the retained module, with packets captured on 0.10.0;
- the row's runs on 0.10.0, recorded and published.

The retained 0.9.2 modules, packets and locks stay frozen, for two reasons: the successors import their inputs from the retained modules, and D6 keeps original references.

**Spec:** The user, 2026-11-01:
- "can we remove 0.9.2?";
- then, after the options (move the 0.9.2-only rows, switch the active setup, keep or delete the old evidence): "which repo are you using? just move to 0.10".

This is recorded as D31: move, do not delete. The repository is `bipxx/vispy_vulkan`.

## Global Constraints

- **Inherited.** Everything in `2026-11-01-napari-010-parity.md`'s Global Constraints still applies: the retained files are never edited, `uv run`, hygiene, expectations before measuring, no skip or xfail, publication rules and D29.
- **`pyproject.toml` and `uv.lock` are not edited.** The Tk candidate's runtime inputs and `compat/metal-ci-reuse.json` (R2's records) pin them, and changing them triggers the Metal wheel workflow. The dev `hosts` group moves to 0.10.0 when R2 renews those records. Until then, the rows use their own locks.
- **CI matrix.** CI runs CPython 3.10 to 3.14. New CPU tests must not depend on the interpreter, so their logic is checked with the bare 3.10 and 3.14 interpreters.
- **Probe versions.** The probe's `NAPARI_VERSIONS` drops 0.9.2 only in Phase 5, once no row needs it.

## Phases (each ends with its own PR)

1. **The napari-threedee plugin suites** (W10 and the plugin parts of W2): threedee, threedee-initialized,
   threedee-overlay, render-plane, render-plane-scheduled and plugin-wheel.
   - First, check that napari-threedee 0.0.29 renders and drags on napari 0.10.0, which changed mouse callbacks.
   - Then add successors of the fixtures, capture tools, native probe and tests, as D30 did.
   - Then capture 0.10.0 packets, build a 0.10.0 plugin runtime lock for the plugin-wheel suite, and run the candidate.
2. **W6** (PySide6 and CPython 3.11, 3.13 and 3.14): the hot-swap gates on 0.10.0 locks for each ABI and binding,
   with W6's qualified wheels.
3. **W7** (WSL lavapipe Linux rows): Linux 0.10.0 host locks, and the guest runs.
4. **The napari-based wheel suites** (`tools/volume_wheel_*`, `tools/image_wheel_probe.py`,
   `tools/volume_scientific_admission.py`): 0.10.0 runtime locks, plus successors where they pin napari.
5. **Retire 0.9.2.**
   - The strict profile's napari patch is regenerated for napari 0.10.0, or dropped if 0.10.0 does not need it.
   - `NAPARI_VERSIONS` becomes `('0.10.0',)`.
   - The consolidated plan marks every 0.9.2 row retired.
   - The `hosts`-group switch is recorded for R2's renewal.

Each phase's tasks are written into this plan when the phase starts, from what its investigation finds.

## Phase 1 tasks (run `napari-010-plugins-299`)

**Feasibility** (done). This was a throwaway probe under upstream vispy, with only the fixture's napari pin bypassed.
- 7 of the 10 live plugin cases pass on napari 0.10.0.
- The 3 drag cases (`overlay/translation`, `scheduled/plane_translation`, `scheduled/plane_rotation`) stop in our own fixture code: `canvas._map_canvas2world` is gone. napari 0.10.0 computes mouse-event positions with `ViewerModel.canvas_to_world` (napari #9517).

1. **`tools/napari_world_position.py`.**
   - `world_position(viewer, canvas, xy)` returns `viewer.canvas_to_world((y, x))` where napari has it, else `canvas._map_canvas2world(xy, canvas.view)`.
   - A CPU contract covers both branches with stand-in objects.
2. **Plugin successor fixtures** `tools/fixture_napari_{threedee_overlay,threedee_initialized,render_plane_scheduled}_successor.py`.
   - Each is generated from its retained module. Its napari pin is removed: the whole statement, or the napari clause of the scheduled fixture's `and` assert.
   - `canvas._map_canvas2world(p, canvas.view)` becomes `world_position(viewer, canvas, p)`.
   - Every mouse move is followed by `QtTest.QTest.qWait(10)`, added where the retained fixture has none (a ruling made in task 6; see Status).
   - The AST contract applies exactly these three transformations to the retained render and requires equality.
3. **`tools/oracle_napari_plugin_successor_capture.py --suite overlay|initialized|scheduled`.**
   - Its behaviour is the retained plugin captures' parent/worker flow and plugin provenance, without the napari pin.
   - It uses the tracked plugin wheel `tests/reference/napari-plugin-wheel-inputs/napari_threedee-0.0.29-py3-none-any.whl` (sha256 `de115619…`).
   - It checks the host lock and keeps it as `host-lock.txt`, and requires a fresh output directory.
   - Packets go to `tests/reference/<base>-napari-<version>/`, with CPU contracts as for D30's tool.
4. **A candidate native probe successor**, for the overlay and render-plane-scheduled workflows.
5. **GPU successor tests**: overlay (5 cases), initialized (retirement only, as on 0.9.2), and scheduled (4 cases), plus the registration proofs in the candidate interpreter. The CI binding contract covers the plugin packets.
6. **GUI runs**:
   - successors on 0.9.2 equal the retained code run now;
   - packets on 0.10.0;
   - candidate under readback and native presentation.
7. **The plugin-wheel suite on a 0.10.0 runtime lock** (Phase 1b, below).
8. **Review and PR.**

## Phase 1b tasks (the plugin-wheel suite)

**Finding.** The retained suite builds its own environment from a runtime lock: napari 0.9.2 with the plugin's dependencies, plus a local asciitree 0.3.3 wheel in place of the lock's sdist-only pin. The 0.10.0 overlay packet keeps its oracle lock as `host-lock.txt`: stock napari 0.10.0 with the same package set, where asciitree 1.0.0 has a wheel. On main, that lock exists only as this snapshot.

1. **`tools/napari_plugin_wheel_suite_successor.py`.**
   - Seven steps are the retained suite's own code objects, rebound to this module's globals: `sources`, `legacy_reference`, `registration_control`, `load_reference`, `worker`, `run` and `main`.
   - They read this module's inputs:
     - the overlay successor fixture's `render`;
     - `LEGACY`, the 0.10.0 overlay packet (manifest sha256 `70b2241a…`);
     - `RUNTIME`, that packet's `host-lock.txt`;
     - `SOURCES`.
   - `compare`, `read_extras` and `interpreter_policy` are the retained functions themselves.
   - Three steps are new:
     - `runtime_requirements`: only the VisPy block is replaced, and asciitree stays as locked;
     - `plugin_info`: the plugin successor capture's `plugin_provenance('overlay', None)`, `HOST_VERSIONS`, and `lock_mismatches(RUNTIME) == []`;
     - `verify_saved`: the retained check, reading `HOST_VERSIONS` and `PLUGIN_WHEEL_SHA256`.
2. **CPU contract** `tests/contract/test_napari_plugin_wheel_suite_successor.py`, in the curated list. It checks:
   - code identity, and that every global the retained code reads is the retained object, apart from the named inputs;
   - that `verify_saved` is the retained one after exactly its two substitutions (AST);
   - that the host versions are the lock's pins, the packet records them, and it keeps the runtime;
   - the runtime, the plugin wheel's digest, the sources and the plugin check;
   - the retained comparison rules, on the 0.10.0 packet.
   - The curated list gets a guard (`test_curated_tests_never_replace_the_entry_modules_own_tests`). CI's entry module star-imports the curated tests at its end, so a curated test named like one of the entry's own tests replaced it there. The guard found three such names among the new tests, and one in `test_positioned_line_comparison` (since D19). All four are renamed.
3. **GPU test** `tests/hosts/test_napari_plugin_wheel_successor_parity.py`: the retained test with the successor suite and `evidence_dir`.
4. **GUI run.**
   - The upstream wheel `c4862155` runs first and must reproduce the packet exactly. Then the candidate test wheel `cc6fa732` runs.
   - The workers' environment is cleaned of `VISPY_*` settings, so they present with Windows' default, readback, as the retained suite's do.
5. **Review and PR.**
