# Installed-wheel mesh/layout regressions

This advances the independent scientific-scene requirement while smooth-line
coverage remains unresolved. All thirteen original release requirements retain
their full scope. Cybersecurity is excluded. New implementation code is AGPL,
with the original unchanged VisPy BSD license and notices attached.

The portable reference packet contains all thirteen original NVIDIA OpenGL
frames, commands, expanded shaders, parameters, CPU text atlases and original
source reports, copied byte-for-byte from the admitted Source4 capture. Its
manifest digest is d4bdd74c7de56c9f2f615f6d0f9d591bf0de3670e762f7fc28b48e356719c153.
Historical candidate evidence is twelve passing cases and a required
axes/colorbar smooth-line refusal. It is not a complete thirteen-case pass.

The portable test keeps every case required, with no skip or expected failure.
One fresh external wheel environment serves thirteen separately waited worker
processes, preserving the original one-case-per-process capture protocol. Each
worker verifies every installed package file against the supplied wheel, actual
compiled-module origins, wheel tags, AGPL and BSD bytes. It compares complete
224x160 RGBA frames, exact alpha, the original per-case RGB tolerance, every CPU
atlas, glyph metadata, font bytes and view rectangles. No alignment, excluded
edge pixels or fitted correction is allowed. The original fixture is unchanged.

Workers retain commands, shaders, image/atlas arrays and native device identity.
They require shutdown and all eight existing resource counters to be zero on
success and failure. The parent records and waits every process, preserves every
failed output, and removes only its newly owned external environment once. An
explicitly supplied existing environment is neither installed into nor deleted.

Use VISPY_TEST_WHEEL to select the archive and VISPY_MESH_LAYOUT_EVIDENCE for a
fresh evidence destination, then run tests/parity/test_mesh_layout_wheel_parity.py.
The default creates a clean environment with locked hashed runtime dependencies.
VISPY_MESH_LAYOUT_PYTHON optionally selects an existing external consumer;
VISPY_TEST_RUNTIME_REQUIREMENTS can supply a hashed requirements file.
VISPY_EXPECTED_BACKEND selects Vulkan or Metal. Software devices require explicit
VISPY_MESH_LAYOUT_ALLOW_SOFTWARE=1 and do not establish native hardware coverage.
Frozen harnesses may bind the canonical repository/reference paths through
VISPY_MESH_LAYOUT_REPOSITORY and VISPY_MESH_LAYOUT_REFERENCE; the reference digest
and fixture source hashes remain mandatory. No duplicate reference arrays are
needed in each harness snapshot.

The corrected source binds each scene with a unique launch ID and records actual
PID/parent/creation time. The parent verifies either its directly waited process
or the single Windows launcher edge, then observes the creation-bound worker's
termination before accepting its output. An unverified worker stops subsequent
launches and prevents environment deletion. PID reuse never causes an unrelated
process to be waited on. The CPU controls exercise the real launcher bridge.

The clean consumer removes inherited VK/DAWN and non-harness VISPY environment
controls. It observes loaded native images before shutdown and rejects repository
images before hashing excluded payloads. Loaded VisPy libraries must be archived
members of the installed wheel. System/runtime libraries are recorded separately;
unavailable system-image hashes are explicit, with no broader driver qualification.
Windows uses PSAPI, Linux executable mappings, and macOS dyld image enumeration;
only the currently exercised Windows path is tested here. These are byte-origin
and lifecycle checks for the renderer experiment, not cybersecurity work.
