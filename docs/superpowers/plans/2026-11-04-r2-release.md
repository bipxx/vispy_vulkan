# R2 release assembly and W11 publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `vispy 0.17.0+vulkan.1`: fresh cp312 wheels for Windows and Linux, built from the final source, with
every mandatory row requalified on them, then a GitHub Release and a PEP 503 index.

**Architecture:** One final source S on the branch `r2/release`: the R2 integration branch (`r2/integration-287`) with
`main` merged in, plus the record renewals that CI validates. The wheels are built fresh from S (D1), qualified as the
release artifacts, and bound into the records before final-head CI and the promotion review. Each phase is its own
registered run.

**Spec:** the consolidated plan's R2, W11 and W15 rows and decisions D1, D2, D18, D31, D32, D33, D34, D35 and D36.
The user, 2026-11-04: "approve" (publish once R2's gates pass), then cp312 Windows + Linux only, an auditwheel-checked manylinux
Linux tag (manylinux_2_39, D35) and the index on this repository's GitHub Pages.

## Global Constraints

- **Minimal, clean and principled** (Standing rules): no step that the decisions do not require; one record per fact.
- **Other owners.** `r2/pending-runtime-patches` and `r2/integration-287` stay as they are; S is a new branch. The
  publication clone's main worktree stays on its owner's branch.
- **Retained files are never edited** (the plan's Standing rules); pinned records are renewed only through their own
  tools or a reviewed renewal script, and each renewal is checked by the validator that reads it.
- **Evidence.** Expectations are written before measuring; failures are kept, never relabeled; no skip or xfail.
- **Hygiene** (AGENTS.md): every phase registers its run; scratch only in `build/work/<run-id>`; each run is closed with
  retention, a cleanup plan, apply and audit before the next starts.
- **No preview** (D2): nothing is published, and no release or index is created, before Phase 5 passes.

## Phases

1. **Final source S** (run `r2-source-309`). Every source and tool change lands here, before the builds.
   - A full worktree of the publication clone on `r2/release`, created from `r2/integration-287`, then `origin/main`
     merged in. The two conflicts resolve to the local plan copy (it carries both sides) and the union of
     `tests/contract/curated_contracts.py`'s modules.
   - D31: the dev `hosts` group moves to napari 0.10.0 (`pyproject.toml`, `uv.lock`, `tests/contract/test_package_inputs.py`).
   - O4: CI's curated list names `tests/contract/curated_contracts.py` directly.
   - D35: release Linux archive records carry auditwheel's manylinux tag; CI's own Linux wheels keep `linux_x86_64`.
   - The plan records D34-D36 and R2's progress.
   - Exit: CI's CPU commands, run locally in a CI-equivalent environment, fail only on the pinned records of Phase 4.
2. **Release wheels** (runs `r2-prep-310`, `r2-wheels-311`). The admission chain fixes the producers:
   - Windows: run `windows-native-proof-94`'s producer protocol from the main tree, synchronized with S (the SDK
     and the prepared build environment it pins live there), then run `wheel-assembly-101`'s backend-only assembly;
   - Linux: a fresh-mode CI production of S (`linux-vulkan.yml`), its capture validated, the wheel checked with
     auditwheel and retagged with its verdict (D35); `runtime-inputs.json` and the CI policy are renewed first.
   Exit: two wheels, 44 of 44 native contracts each, exact archive joins pass.
3. **Qualification on the release wheels** (runs `r2-strict-312` and later):
   - the 8 strict rows (D32) and W15's stock napari gates on Windows and WSL;
   - the hot-swap rows the plan closes at R2: the napari parity suites, Glue's five workflows, the mesh scenes and W7's
     Linux rows (the release changes native capture since they last ran);
   - the installed Tk protocols that the admission chain requires, and the two Tk source-functional observations.
4. **Records, binding and promotion** (run `r2-records-315`, then the promotion run), renewed once with the artifacts known:
   - the Tk candidates' runtime inputs, required rows (D32) and reseals; the compatibility inventory's and execution
     ledger's pins; the CI policy's workflow hashes; the native and Linux native protocol pins;
   - the matrix: D32's optional host rows, the napari 0.10.0 successor rows, and the release wheels bound into the 8 rows;
   - independent source, scope and promotion reviews; fresh Linux and Metal CI builds to renew their reuse records;
     final-head CI, the 23-job bundle and the promotion envelope; merge; the local tree synchronized with `main`.
5. **W11 publication** (its own run): a new GitHub Release with the two wheels (the draft
   `v0.17.0-vulkan.1-rc.1` stays untouched); the index on GitHub Pages; a clean venv installs from the channel and the
   W2 smoke test passes; release notes with D33's startup-stall text; dated status updates.

Each phase's tasks are written into this plan when the phase starts, from what its investigation finds.
